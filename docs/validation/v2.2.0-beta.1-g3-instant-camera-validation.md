# v2.2.0-beta.1 G3 Instant integrated camera validation

## Scope

A controlled production-candidate test was performed on 2026-09-06 at 21:03–21:05 EDT after explicit approval to override the normal 8 AM–8 PM audible-test window.

The test was intentionally limited to one explicitly configured **G3 Instant** camera target. It did not test or claim support for any other camera model or codec profile.

## Capability gate

The configured camera was accepted only after startup capability inspection. The sanitized `/targets` catalog reported:

- target type: camera;
- model: UVC G3 Instant;
- status: available;
- announce: supported;
- repeat: supported;
- volume, preset, assigned-default, and buzzer: unsupported.

Home Assistant loaded the matching candidate and created only the capability-appropriate notification, text announcement media-player, queue-depth, and last-result entities for this target.

## Audible result

The physical Protect speaker level was temporarily set to 50% through its existing device-managed entity and verified before each request. UniFi Announcer did not receive or apply a per-request camera volume override.

The same short test sentence was sent in two separate, explicitly authorized single-play requests. The second request was requested as a replay by the listener. The listener confirmed that the replay produced **clear and correct speech** from the intended G3 Instant.

For both requests:

- Home Assistant accepted the service call;
- the Announcer camera result was `success`;
- the camera queue returned to zero;
- no retry was observed on these successful requests;
- the complete Smart Chime slot-status fingerprint was identical before and after playback.

The unchanged slot fingerprint proves no observable slot-state change, but it does not independently instrument or prove that no write call occurred.

The Protect speaker level was restored to its original 100% value and verified after each request.

## Supplemental gate completion

The remaining beta.1 gates were completed in the same approved test session:

- **Instrumented no-write boundary:** all eight camera-focused dispatcher tests passed. The camera-only test specifically asserts that `dynamic_slots.prepare` is not awaited.
- **Post-restart playback:** Announcer was restarted, returned healthy at the exact runtime SHA, revalidated the camera capability, and produced clear and correct speech after restart.
- **Repeat behavior:** one API request with `repeat_times=2` produced exactly two clear, sequential, non-overlapping repetitions as physically confirmed by the listener.
- **Uncertain failure:** a fault-injection transport recorded a possibly delivered first send and then raised. Exactly one negotiation, one connection, and one send attempt occurred; the socket closed without reconnect or replay. This assertion is retained as a regression test.
- **Unavailable mixed group:** a temporary group containing the existing Smart Chime and a deliberately nonexistent camera was rejected in 7 ms with HTTP 400 before synthesis. The slot-state fingerprint and overwrite counter remained unchanged at zero, and no TTS synthesis was observed.

The temporary unavailable camera and mixed group were removed afterward. Announcer was recreated from the verified single-camera configuration and returned healthy with only the configured camera available and both Smart Chime slots ready.

## Compatibility boundary

This result validates the integrated AAC/ADTS path only for the exact runtime candidate and one G3 Instant. It does **not** establish generic camera support.

Additional camera models and unsupported Opus/RTP profiles are compatibility limitations, not beta.1 release gates. They remain outside the supported model/profile claim.

No tag, GitHub release, image publication, PR merge, or stable promotion was performed.
