## Gate 1 — native `tts.speak` to one Smart Chime

1. Select a Home Assistant TTS provider that is known to synthesize correctly.
2. Target one UniFi Announcer Smart Chime media-player entity with `tts.speak`.
3. Use a unique phrase that cannot be confused with cached prior speech.
4. Observe the Home Assistant action result and Announcer logs/status.
5. Confirm in the room that the exact phrase is audible and intelligible once.

Pass criteria:

- [ ] HA resolves a media-source item and calls the Announcer media path.
- [ ] Announcer accepts/normalizes the audio and returns a canonical non-failure disposition.
- [ ] The intended Smart Chime plays the expected phrase once.
- [ ] No unintended target produces audio.
- [ ] Last playback result updates consistently with the dispatcher outcome.

## Gate 2 — repeated native `tts.speak` / fixed-slot behavior

Run the same phrase again, then a distinct phrase, then the first phrase again.

Pass criteria:

- [ ] Every audible phrase matches the request order.
- [ ] Exactly the existing two service-owned dynamic TTS identities remain in use.
- [ ] No stale or cross-request audio is heard.
- [ ] Existing resident-content/boot-continuity safety remains intact.

## Gate 3 — accepted non-MP3 media normalization

Use one short Home Assistant media-source clip in an accepted non-MP3 format, preferably WAV or FLAC.

Pass criteria:

- [ ] HA resolves and forwards bounded bytes.
- [ ] Backend normalization succeeds.
- [ ] Intended Smart Chime plays the correct audio.
- [ ] No additional Protect ringtone identity is allocated per media item.

Record input MIME type and approximate clip duration without embedding the media itself.

## Gate 6 — rejection before physical playback

Test each case separately against an otherwise valid target:

- [ ] body larger than configured `MEDIA_MAX_INPUT_BYTES` → rejected before dispatch/playback;
- [ ] duration over `MEDIA_MAX_DURATION_SECONDS` → rejected before dispatch/playback;
- [ ] unsupported declared MIME type → rejected before decode/dispatch;
- [ ] invalid bytes under a supported MIME type → rejected before dispatch/playback;
- [ ] compressed request body → rejected;
- [ ] missing/bad application API key → rejected;
- [ ] arbitrary direct URL supplied to the HA media player → rejected rather than fetched.

Pass criteria: no physical device emits audio for any rejection case.
